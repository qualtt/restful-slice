### Команда:
* **Виталий (DevOps)** возьмет на себя всю инфраструктуру, CI/CD, Nginx и написание базовых оберток для работы с внешними системами.
* **Илья (3D/API)** сфокусируется на контрактах (API), бизнес-логике нарезки, работе со слайсером и эндпоинтах.
* **Алексей (Backend/DB)** возьмет на себя бэкенд (работу с базой данных, бизнес-логику биллинга и заказов)


---

### Этап 1: Проектирование и архитектура
**Цель:** Спроектировать контракты, инфраструктуру и БД, чтобы на этапе разработки не блокировать друг друга.

*   **Виталий:**
    *   Проектирование инфраструктурной схемы: как взаимодействуют Nginx, микросервисы, RabbitMQ, PostgreSQL, MinIO.
    *   Составление требований к окружению (`.env` файлы, секреты).
    *   Выбор и согласование с командой линтеров и настройка правил для Git hooks (чтобы код-стайл был единым).
*   **Илья:**
    *   Проектирование внешнего REST API по стандартам (API Design Guide). Составление OpenAPI спецификации для эндпоинтов загрузки STL, выбора пресета, проверки статуса.
    *   Сбор требований по 3D-печати: какие параметры пресетов нужно учитывать (заполнение, поддержки и т.д.).
*   **Алексей:**
    *   Проектирование контрактов (сообщений) для очереди: что именно передается воркеру нарезки и что он возвращает.
    *   Таблицы: `Orders` (заказы и их статусы), `Inventory` (катушки, вес, цена), `Presets`.
    *   Проектирование реляционной структуры БД (ER-диаграммы).

---

### Этап 2: Основная разработка и юнит-тестирование
**Цель:** Написать код сервисов, покрыть тестами бизнес-логику и настроить CI-пайплайн.

*   **Виталий:**
    *   Настройка репозитория: внедрение Git hooks (`pre-commit`) и базового CI/CD (GitHub Actions для автоматического запуска линтеров и тестов).
    *   Написание базового инфраструктурного кода (модулей/адаптеров), которые будут использовать другие: функции загрузки/скачивания файлов в MinIO и функции публикации/подписки для очереди сообщений.
    *   Настройка Nginx в качестве Reverse Proxy (проксирование запросов к нужным микросервисам, ограничение размера загружаемого файла и тд).
*   **Илья:**
    *   Разработка **Slicing Worker Service**: сервис-подписчик, который забирает задачу из очереди, скачивает STL, вызывает Orca Slicer CLI/API с нужным пресетом.
    *   Парсинг результатов (вытаскивание граммов, метров и времени печати из логов или G-code).
    *   Написание unit-тестов для логики парсинга и валидации STL-файлов.
*   **Алексей:**
    *   Разработка **Order Service** (CRUD для заказов) и **Inventory Service** (учет остатков пластика).
    *   Реализация математики: расчет стоимости на основе времени и потраченного веса, списание остатков (с проверкой, что пластик не ушел в минус).
    *   Написание unit-тестов для калькулятора стоимости и логики обновления статусов в БД.

### Этап 3: Сборка, контейнеризация
**Цель:** Упаковать приложение, провести сквозное тестирование, обработать внештатные ситуации.

*   **Виталий:**
    *   Написание оптимизированных `Dockerfile` для всех трех микросервисов (multi-stage сборка для уменьшения веса образов).
    *   Создание общего `docker-compose.yml`, поднимающего всю систему одной командой (БД, S3, очередь, Nginx, микросервисы).
    *   Настройка логгирования (чтобы логи всех контейнеров были легко доступны для отладки).
*   **Илья:**
    *   Наполнение системы тестовыми 3D-данными: создание базовых пресетов печати (Draft, Standard, High Quality) в БД/MinIO.
    *   Обработка ошибок нарезки: реализация логики, когда слайсер падает из-за битого STL-файла (возврат понятной ошибки пользователю через API).
    *   Проведение сквозного тестирования (E2E) API через Postman/Insomnia от загрузки до получения итоговой стоимости.
*   **Алексей:**
    *   Написание миграций для базы данных (автоматическое создание таблиц при старте контейнера БД).
    *   Реализация транзакционности / компенсаторных действий: если нарезка упала (о чем сообщит Участник 2), статус заказа меняется на "Ошибка" и зарезервированный пластик возвращается на баланс склада.
    *   Сборка документации (Swagger UI) и оформление финального отчета по лабораторной.
